# Finding 07: Unnecessary Open Ports & Exposed Services

| Item | Detail |
|------|--------|
| **Kerentanan** | Unnecessary Open Ports & Exposed Administrative Services |
| **Severity** | High |
| **Skor CVSS** | 8.6 (`CVSS:4.0/AV:N/AC:L/AT:N/PR:L/UI:N/VC:H/VI:H/VA:N/SC:N/SI:N/SA:N`)
| **Target PoC** | `192.168.56.105:22`, `192.168.56.105:3306` |
| **Port / Service** | `22/tcp` (SSH), `3306/tcp` (MySQL Database) |

---

## Deskripsi

Kerentanan ini terjadi karena server membuka port layanan sensitif dan administratif langsung ke jaringan publik tanpa adanya pembatasan akses (*firewalling*). Layanan seperti database MySQL (`3306`) atau remote access SSH (`22`) yang seharusnya hanya dapat diakses secara lokal atau melalui VPN internal kini dapat dijangkau oleh siapapun dari luar.

---

## Dampak

- Penyerang dapat melakukan percobaan login secara masif (Brute Force & Password Spraying) terhadap port layanan terbuka seperti SSH atau MySQL.
- Terbukanya port membuka celah eksploitasi layanan jika versi layanan yang berjalan memiliki kerentanan yang diketahui (CVE).
- Terbukanya port memberikan akses langsung ke database dari jaringan publik jika terdapat kelemahan pada otentikasi.

---

## Rekomendasi Perbaikan

- Terapkan firewall rules menggunakan `ufw` atau `iptables` untuk memblokir port `3306` dan membatasi port `22` (SSH) hanya untuk IP tepercaya (*IP Whitelisting*).
- Konfigurasikan database agar hanya diakses dengan melalui jaringan lokal dengan IP terpercaya
- Gunakan Virtual Private Network (VPN) untuk seluruh saluran akses manajemen server secara terisolasi.

### Contoh Konfigurasi

```bash
# UFW Firewall Rules (Ubuntu/Debian)
sudo ufw default deny incoming
sudo ufw allow 80/tcp
sudo ufw allow 8083/tcp
sudo ufw allow from 192.168.56.1 to any port 22 proto tcp
sudo ufw enable
```

```ini
# MySQL Configuration (/etc/mysql/mysql.conf.d/mysqld.cnf)
[mysqld]
bind-address = 127.0.0.1
```

## Langkah Proof of Concept (PoC)

### Langkah 1 — Mencoba koneksi remote langsung ke port MySQL (3306)

Menggunakan credential yang ada di file `.env` (hasil temuan `FIND-06`) untuk melakukan akses database secara langsung dari jaringan luar.

**Credential dari file `.env`:**

```env
DB_HOST=192.168.56.105
DB_PORT=3306
DB_DATABASE=klaimku
DB_USERNAME=klaimku_app
DB_PASSWORD=klaimku_app_pw
```

**Command:**

```bash
mysql -h 192.168.56.105 -u klaimku_app -p'klaimku_app_pw'
```

**Output:**

```text
Welcome to the MySQL monitor.  Commands end with ; or \g.
Your MySQL connection id is 12
Server version: 8.0.36-0ubuntu0.22.04.1 (Ubuntu)

mysql> SHOW DATABASES;
+--------------------+
| Database           |
+--------------------+
| information_schema |
| klaimku            |
+--------------------+
```

> **Capture 1:** Koneksi berhasil ke database MySQL dari jaringan luar menggunakan credential dari file `.env`

### Langkah 2 — Mencoba akses remote ke layanan SSH (port 22)

Layanan SSH terbuka bagi siapapun dari jaringan luar sehingga penyerang dapat melakukan percobaan login secara langsung (Brute Force) tanpa pembatasan IP.

**Command:**

```bash
ssh administrator@192.168.56.105
```

**Output:**

```text
The authenticity of host '192.168.56.105' can't be established.
ED25519 key fingerprint is SHA256:xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx.
Are you sure you want to continue connecting (yes/no/[fingerprint])?
```

> **Capture 2:** Layanan SSH (port 22) terbuka dan dapat diakses dari jaringan publik
